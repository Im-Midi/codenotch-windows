Validation limits

  • Physical monitors on this machine were all at 100% DPI. Mixed-DPI geometry is tested in code; changing real monitor DPI, unplug/reconnect, sleep/resume and full-screen transitions still need hardware acceptance.
  • The full demo interaction suite was not rerun after correcting an initial demo snapshot timing issue; further visible movement tests were stopped after the user noticed the position changes. The live card was retested without changing placement. Provider-order/collapse automation and corner hover transitions remain to be completed.
  • Claude credentials and Antigravity installation were unavailable to doctor. Cursor was present but its local authentication could not be read. Other provider account usage was not live-validated. Missing readings are reported as unavailable, not 0%.
  • Installer install/uninstall, ten-minute idle CPU/memory/wakeup measurement and an overnight stability run remain unperformed. The installer is unsigned. No performance or long-run stability claim is made.

Demo data requires an explicit --demo argument. Standalone browser sample data requires ?preview=1 and cannot activate on the native Tauri origin. Normal application startup uses the system readers. The original plan below remains as scope and design history.

Recommended route

Extend the existing Windows port using Rust + Tauri 2. Keep its plain HTML, CSS and JavaScript interface. The repository now contains a Windows implementation, so a complete rewrite is unnecessary. Its main placement gap is that the current code pins the notch to the primary monitor's right edge. Source: placement implementation.

For an independent C# application, use .NET 10 and WPF. That is the preferred alternative if maintaining everything in C# matters more than reusing this implementation.

SettingProposed behavior
DisplaySelect any connected monitor by friendly name and resolution. Remember its Windows display identity, not a temporary list index. Show the chosen display in Settings.
Edge and positionRight, left, top or bottom. Side edges stack vertically; top and bottom stack horizontally. Default to right, centered. Offer an along-edge slider and an explicit unlock-to-drag action; persist a normalized offset for each edge.

VisibilityDefault to visible rings. Optional collapse-to-tab on pointer exit, always-on-top toggle, size control and hide while a full-screen application occupies the selected monitor. Keep a tray route to show it again.
Providers and readingsCodex first, with Claude as the second visual reference. Retain existing Cursor and Antigravity readers. Enable, hide and reorder providers. Default Codex's headline ring to weekly usage when present; otherwise label the available window explicitly.
Desktop integrationTray commands for Settings, refresh, show/hide, reset placement and quit. Start with Windows is opt-in. Settings may take focus; passive hover must not interrupt typing in another application.
RecoveryIf a monitor disconnects, temporarily use the primary display while retaining the saved preference. Recalculate bounds after reconnect, DPI change, taskbar changes, sleep and resume. Clamp the complete card inside the selected display.

All transparent areas must pass mouse input through to applications underneath. Restrict hit testing to the visible notch and card. For keyboard users, provide an explicit focusable detail view through the tray; support Escape, visible focus, readable labels and reduced motion.

Keep logical layout units separate from physical desktop coordinates, including negative coordinates on monitors left of the primary display. Microsoft documents the need to handle per-monitor DPI transitions: Windows DPI guidance. Ordinary topmost windows do not guarantee visibility over exclusive full-screen applications or the secure desktop.

04 / Where the information comes from

The visual design is straightforward. Data compatibility is the first implementation checkpoint. Account usage limits and session activity are separate feeds; neither should be inferred from the other.

InformationExisting source and required treatment
Codex usageThe Windows adapter reads the local Codex sign-in for an internal ChatGPT usage request and falls back to rate-limit records in rollout files. Verify the current payload before depending on it. Retain the original reading timestamp; show cached/stale data visibly. Codex adapter.
Codex activityThe inspected code reads a local desktop turn database and falls back to rollout events and timing rules. These are version-sensitive. Test start, completion, abort and waiting states on the installed version. Label heuristic results as inferred; show unknown when the source cannot distinguish working from waiting. Activity reader.
Other providersThe Windows port includes Claude, Cursor and Antigravity sources. Validate each installed provider separately; unsupported or unavailable quota data must remain unavailable rather than becoming a zero. Provider overview.
Credential handlingKeep borrowed credentials read-only and inside the native backend. Never expose them to web content, logs or settings exports. Reauthentication belongs to the owning tool. Add an explicit Codex profile path and honor CODEX_HOME; the inspected Windows helper currently defaults to the home directory's .codex folder.

Use a small shared reading shape: provider, usage windows, used percentage, reset time, source timestamp, freshness, activity and activity confidence. A missing weekly window is not 0% weekly usage. Do not reset a reading locally just because its reset time has passed; fetch a new reading or mark the old one stale.

Preserve the existing polling/backoff behavior until measured. Proposed cadence is about 60 seconds for quota, slower when idle, with bounded local activity reads. Honor rate limits and timeouts, avoid overlapping requests, and do not let manual refresh bypass a provider's cooldown. Local development must use synthetic fixtures before live reads.

These integrations are internal endpoints and local file/database formats, not a stable public API contract. The upstream caveat explicitly describes that limitation. Live account access was not exercised for this plan.

06 / Definition of done

Automated checks

  • Geometry covers all four edges, negative monitor coordinates, small displays and 100%, 125%, 150% and 200% scaling.
  • Settings survive restart, missing fields and invalid values. A failed save leaves the previous file intact.
  • Usage fixtures cover 0%, 6%, 100%, missing windows, timestamp units, malformed responses, expired auth and backoff.
  • Activity fixtures cover working, waiting, completed, aborted and stale sessions without promoting a guess to confirmed state.

Manual Windows checks

  • The right-edge view matches the supplied reference in shape, hierarchy and spacing.
  • Choose any attached monitor and each edge; restart, unplug and reconnect without losing the notch.
  • Move between different display scales; no blurry text, clipping, card flicker or misplaced click targets.
  • Typing continues in the foreground app during hover. Transparent areas pass clicks through.
  • Test pointer travel, keyboard detail access, Escape, taskbar access, full-screen hiding and sleep/resume.
  • Compare usage to the owning tool at the same time. Verify sign-out and network failure are visible.

Record idle CPU, working memory and wakeups after ten minutes, including WebView2 processes. Target under 1% average CPU on the test machine and stable memory during an overnight run; report measurements instead of assuming a framework is lightweight.

Initial delivery targets Windows 11 x64, one selected display and existing providers. Additional provider integrations, multiple simultaneous notches, cloud settings sync, automatic updates and ARM64 builds remain separate work. No new database, hosted service or plugin framework is needed.
